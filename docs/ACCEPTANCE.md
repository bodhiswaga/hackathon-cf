# Соответствие ТЗ CampusFlow

Повторная проверка: 16 ноября 2026. Источник — все 25 страниц исходного PDF в корне репозитория. Обязательными являются MVP и восемь сценариев приёмки; рекомендации и дополнительные возможности на странице 14 — бонусы.

## Обязательная функциональность

| Требование ТЗ | Реализация |
|---|---|
| Python / C# / Java; SQLite / PostgreSQL | Python FastAPI; обе СУБД поддержаны и проверены |
| User, Room, Booking и обязательные поля | backend/models.py, JSON в camelCase |
| Справочник, корпус, этаж, вместимость, оборудование | API, поиск студента, CRUD администратора |
| Фильтры и свободные слоты на дату | /api/rooms и /api/rooms/{id}/free-slots; календарь и сетка |
| Создание, просмотр своих броней, отмена и история | POST /api/bookings, GET /api/bookings/my, DELETE /api/bookings/{id} |
| Проверка всех видов пересечения, касание границ допустимо | Полуоткрытые интервалы; 409 BOOKING_CONFLICT |
| Защита от конкурентного бронирования | PostgreSQL FOR UPDATE на аудитории; SQLite BEGIN IMMEDIATE |
| Права студента и администратора на API | Чужая бронь — 403; admin-endpoints — только admin; admin не создаёт бронь |
| Все брони, отмена любой, управление аудиториями | Админ-панель; удаление комнаты архивирует её, сохраняя историю |
| Статистика по дням и корпусам | Недельная загрузка кампуса; API /api/admin/stats |
| Не менее 10 комнат, 3 пользователей, несколько дат | Демо seed: 12 комнат, 3 пользователя, 56 броней на 8 дней |
| REST /api, JSON, документация | Swagger/OpenAPI в демо; краткий контракт и ограничения в README |
| Запуск с нуля, README, 5-минутное демо | Два Compose-режима; README; docs/DEMO.md |

Демо выполняет приёмку на seed-данных. Prod-ready намеренно стартует без учебных пользователей и комнат: оператор создаёт администратора и реальные аудитории, студенты регистрируются по приглашению.

Команды README проверены на новых volumes, отдельными Compose-проектами campusflow-readme-demo и campusflow-readme-prod. Рабочие volumes не очищались.

## Бонусы и дополнительные функции

- Реализованы: JWT, аналитика загрузки, Docker Compose, тесты конфликтов, CSV. Также есть регистрация, приглашения, смена пароля, отзыв сессий, аудит, экспорт .ics, светлая/тёмная/системная тема.
- Отдельный рекомендатель трёх аудиторий из бонусов не реализован; доступен фильтр свободных комнат. ML, интеграция с расписанием вуза и почтовая отправка не входят в обязательный MVP.

## Профиль и интерфейс

Аватар и имя внизу боковой панели открывают настройки вместо отдельного пункта «Мой аккаунт». Страница разделена на личные данные, пароль, оформление и сессии. Сохранение имени отражается в панели; есть отмена правок, отдельные сообщения форм, показ/скрытие паролей, подтверждение завершения сессий.

Тема меняется за 300 мс; переключатели профиля и верхней панели синхронизированы. При prefers-reduced-motion переход отключён. На ширине 375 px горизонтального переполнения нет; закрытая мобильная панель недоступна для случайной клавиатурной фокусировки. Проверки смены пароля и отзыва сессий выполнены API-тестами; браузером проверены вход через аватар, сохранение/отмена имени, оформление, мобильное меню и диалог сессий.

## Границы результата

Обязательный MVP реализован и проходит приёмку. Продолжительная нагрузка и гарантия доступности не входят в ТЗ. Бесплатные Render/cron-job.org имеют ограничения часов работы, хранения демо и срока жизни PostgreSQL; они указаны в README. Новые изменения интерфейса появятся на публичных сайтах после push и успешного деплоя Render.
