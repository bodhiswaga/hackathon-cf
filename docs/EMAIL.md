# Бесплатная почта CampusFlow через Gmail

Используем отдельный Gmail и Google Apps Script. Покупать домен, подключать карту и передавать пароль Gmail приложению не нужно. Почтовая очередь CampusFlow отправляет подписанные HTTPS-запросы; скрипт выполняет отправку от имени своего владельца.

Обычный Google-аккаунт имеет квоту Apps Script 100 получателей за 24 часа. Демо и prod, использующие один аккаунт, делят эту квоту. Десять писем десяти участникам расходуют десять единиц. Google может менять ограничения; проверяйте [официальные квоты](https://developers.google.com/apps-script/guides/services/quotas).

## 1. Подготовить Google

1. Создайте отдельный Gmail для CampusFlow либо выберите уже существующий отдельный аккаунт. Войдите именно в него.
2. Откройте [script.google.com](https://script.google.com/) и создайте **Новый проект**. Назовите его `CampusFlow Mail`.
3. Откройте [Code.gs из проекта](../scripts/google-mail/Code.gs), скопируйте весь текст и замените им содержимое файла `Код.gs` / `Code.gs` в редакторе Google. Сохраните.
4. В настройках проекта включите отображение файла манифеста `appsscript.json`. Замените его содержимое текстом из [нашего appsscript.json](../scripts/google-mail/appsscript.json). Он запрашивает только право отправки почты, без чтения входящих писем.
5. Создайте два независимых секрета в PowerShell на своём компьютере:

```powershell
python -c "import secrets; print('GOOGLE_MAIL_SECRET=' + secrets.token_hex(32)); print('NOTIFICATIONS_JOB_SECRET=' + secrets.token_hex(32))"
```

6. В настройках проекта Google найдите **Свойства скрипта / Script properties**, добавьте свойство `CAMPUSFLOW_MAIL_SECRET`. Значение — созданный `GOOGLE_MAIL_SECRET` (только строка после знака `=`).
7. В редакторе выберите функцию **authorizeMail** и нажмите **Выполнить**. Разрешите отправку писем от выбранного Google-аккаунта. В журнале должна появиться оставшаяся квота. Этот шаг письма не отправляет. Разрешайте доступ только своему проекту с проверенным кодом.

Пароль Gmail и секреты не публикуйте в Git или чате.

## 2. Опубликовать скрипт

Нажмите **Развернуть / Deploy → Новое развёртывание / New deployment**:

- Тип: **Веб-приложение / Web app**.
- Выполнять от имени: **Я / Me**.
- Доступ: **Все / Anyone**, включая пользователей без входа в Google. Это нужно для серверных запросов Render; отправка при этом разрешается только по действительной подписи.

Завершите развёртывание и скопируйте URL вида `https://script.google.com/macros/s/…/exec`. Нужен именно `/exec`, а не `/dev`. Открыв URL в браузере без входа, вы должны увидеть только JSON `CampusFlow mail`, без писем и настроек. Если доступ ограничен политикой учебного Google Workspace, используйте отдельный обычный Gmail.

При изменении кода в Google нужно обновлять развёртывание: **Управление развёртываниями → Изменить → Новая версия**. Изменение свойства секрета применяется без новой версии кода.

## 3. Подключить Render

В **Render → Web Service → Environment** добавьте:

| Переменная | Значение |
|---|---|
| `MAIL_PROVIDER` | `google-apps-script` |
| `GOOGLE_MAIL_URL` | URL опубликованного скрипта, заканчивающийся `/exec` |
| `GOOGLE_MAIL_SECRET` | Тот же секрет, что в свойстве `CAMPUSFLOW_MAIL_SECRET` Google |
| `PUBLIC_URL` | `https://campusflow-production.onrender.com` для prod; `https://campusflow-78s7.onrender.com` для демо |
| `NOTIFICATIONS_JOB_SECRET` | Второй независимый секрет, только для задания cron |

Сохраните Environment с перезапуском. Для Google не нужны `RESEND_API_KEY` и `MAIL_FROM`. Можно использовать один Google-скрипт для двух сайтов: адреса `PUBLIC_URL` должны быть разными, а секрет Google — совпадать со свойством скрипта. Рекомендуются отдельные ключи cron для двух сервисов. Почта одного Gmail имеет общую квоту.

Для локального Compose эти же переменные поддерживаются в окружении / `.env.production`. `PUBLIC_URL` должен открываться на компьютере пользователя. Веб-приложение не принимает произвольный адрес сервера отправки: разрешены только HTTPS URL Google Apps Script.

## 4. Включить доставку по расписанию

В [cron-job.org](https://console.cron-job.org/) создайте отдельное задание:

- URL prod: `https://campusflow-production.onrender.com/api/jobs/notifications`.
- URL демо: `https://campusflow-78s7.onrender.com/api/jobs/notifications`.
- Метод: **POST**, тело пустое.
- Заголовок: `Authorization: Bearer <NOTIFICATIONS_JOB_SECRET соответствующего сайта>`.
- Интервал: **1 минута** на время показа / в рабочие часы.
- Таймаут: до 60 секунд; уведомления о сбое включены.

При двух сайтах создаются два задания. **Test run** возвращает HTTP 200 с `sent` и `processed`. Без правильного ключа ожидается 401; без настроенного транспорта — 503. Задание доставки само создаёт входящий трафик: дополнительные health-запросы не требуются для поддержания активности в то же время. Два сайта расходуют общие 750 часов Render; не включайте оба круглосуточно на весь месяц. Ночью без задания доставка и напоминания могут задерживаться.

## 5. Проверить настоящее письмо

1. Откройте CampusFlow → профиль → «Почтовые уведомления». Укажите доступный вам адрес получателя и сохраните.
2. Запустите Test run задания cron. В профиле нажмите **Обновить статус**. Должен появиться статус «Передано отправителю».
3. Проверьте входящие и «Спам». Откройте письмо и подтвердите email кнопкой на странице. Ссылка одноразовая, действует час.
4. Создайте бронь, затем отмените её. Проверьте оба уведомления.
5. Проверьте предложение очереди, командную встречу и напоминание в течение часа до начала. Отключите один тип уведомлений и убедитесь, что новые письма этого типа не создаются.

Смена email требует нового подтверждения. В приложении доступны последние 20 писем пользователя: состояние отправки, исчерпанная квота и неоднозначный результат доставки. Факт вызова MailApp не гарантирует попадание во входящие; окончательную доставку проверяют в почтовом ящике получателя.

## Повторы и ограничения

Очередь сохраняется в базе, за запуск обрабатывается до 10 писем. Google-запросы подписаны HMAC-SHA256 и действуют 5 минут. Скрипт проверяет подпись, адрес единственного получателя и идентификатор письма. Одновременные запросы защищены блокировкой. Сохраняются только идентификаторы и хеши результата; адреса и текст в свойства Google не записываются. Идентификаторы демо и prod различаются.

При исчерпании квоты письмо остаётся в очереди с повтором через час, без расходования лимита сетевых попыток. Неактуальные подтверждения, предложения и напоминания пропускаются. Обычные Google-письма старше 46 часов также пропускаются; записи защиты от повторов хранятся в скрипте 48 часов. Сетевые ошибки повторяются с задержкой, максимум пять неудачных попыток.

Если Google успел начать отправку, но не подтвердил результат, автоматическая повторная отправка блокируется и показывается «Результат отправки не подтверждён». Оператор должен проверить доставку: гарантировать ровно одну доставку при сбое между MailApp и записью результата невозможно. Это предотвращает слепые дубли, но в такой ситуации возможен пропуск письма.

Квота 100 получателей — ограничение Google, её нельзя снять настройкой cron. Для массовой эксплуатации потребуется другой тариф или почтовый сервис. Приглашения в команды передаются ссылкой вручную; ежедневные сводки и вложения календаря пока не реализованы.

## Резервный транспорт Resend

Существующая интеграция сохранена. Для неё задайте `MAIL_PROVIDER=resend`, `RESEND_API_KEY`, `MAIL_FROM` с подтверждённым доменом, `PUBLIC_URL` и `NOTIFICATIONS_JOB_SECRET`. Доставка запускается тем же заданием cron. Для Resend действует прежнее ограничение повторов письма в 23 часа.
