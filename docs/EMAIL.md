# Подключение почты CampusFlow

Почтовый механизм реализован, но без настройки провайдера настоящие письма не отправляются. Команды, голосования и бронирования работают независимо от почты.

## Отправитель

1. Создайте аккаунт [Resend](https://resend.com) и добавьте свой домен в Domains. Выполните DNS-настройки, которые покажет Resend, и дождитесь подтверждения. Домен предоставляется отдельно; проект не покупает домены и платные тарифы.
2. Создайте API-ключ с правом отправки. Не публикуйте его в Git или чате.
3. В Render → нужный Web Service → Environment добавьте:

| Переменная | Значение |
|---|---|
| `RESEND_API_KEY` | Ключ отправки Resend |
| `MAIL_FROM` | Например, `CampusFlow <notifications@ваш-домен.ru>` с подтверждённым доменом |
| `PUBLIC_URL` | Полный HTTPS-адрес именно этого сайта, без пути |
| `NOTIFICATIONS_JOB_SECRET` | Независимая случайная строка минимум 32 символа |

Секрет задания можно создать командой `python -c "import secrets; print(secrets.token_hex(32))"`. Примените Environment с перезапуском сервиса. Для двух сайтов задайте разные `PUBLIC_URL` и секреты задания. При локальном Compose-запуске переменные передаются из окружения / `.env.production`; адрес подтверждения должен открываться на компьютере пользователя.

## Задание доставки

В cron-job.org создайте отдельное задание, дополнительно к GET health:

- URL: `https://адрес-сайта/api/jobs/notifications`.
- Метод: **POST**; тело не требуется.
- Заголовок: `Authorization: Bearer <NOTIFICATIONS_JOB_SECRET>`.
- Интервал: **1 минута** в рабочие часы / на время демонстрации.
- Таймаут: до 60 секунд; включите уведомления о сбоях.

Test run должен вернуть HTTP 200 и JSON с `sent` и `processed`. Без ключа ожидается 401; без настроенного провайдера — 503. Задание каждую минуту поддерживает сервис активным и расходует общую квоту Render: согласуйте расписание двух сайтов с ограничениями из README. Ночью без задания письма не доставляются, напоминания могут быть пропущены.

За запуск обрабатывается до 10 писем. Ошибки провайдера оставляют письмо в очереди, после пяти неудачных попыток оно получает статус failed. Сетевой вызов выполняется вне транзакции бронирования. Используется ключ идемпотентности Resend, письмо старше 23 часов не отправляется повторно. Истёкшие подтверждения, предложения очереди и напоминания пропускаются. После ответа провайдера sent означает принятие API, а не гарантированное попадание во входящие; фактическую доставку проверяйте в Resend Logs.

## Проверка пользователем

1. Откройте профиль и укажите свой email.
2. Выберите события и сохраните настройки. До подтверждения адреса обычные уведомления не отправляются.
3. Дождитесь задания доставки, откройте письмо и подтвердите адрес кнопкой на странице. Ссылка одноразовая и действует час. Смена email требует нового подтверждения.
4. Создайте встречу; проверьте письмо и запись в Resend Logs. Проверьте отключение выбранного типа уведомлений.

Доступны новые встречи / изменения обычных броней, командные голосования, вступление в команду, предложения очереди и напоминания в течение часа до начала. Приглашение вступить в команду передаётся ссылкой вручную. Сводка за день, вложения календаря и автоматическая отправка приглашений на произвольные адреса не реализованы.
