# CampusFlow

Сервис для поиска аудиторий и организации встреч в кампусе. Позволяет проверить занятость, забронировать помещение, согласовать время с командой и найти замену отменённой аудитории.

**Стек:** React · TypeScript · FastAPI · SQLAlchemy · PostgreSQL / SQLite.

## Открыть сайт

| Версия | Ссылка | Вход |
|---|---|---|
| Демо хакатона | [Открыть демо](https://campusflow-78s7.onrender.com) | Учебные аккаунты из таблицы ниже |
| Prod-ready | [Открыть рабочую версию](https://campusflow-production.onrender.com) | Личный аккаунт; регистрация по коду приглашения |

На бесплатном Render после простоя сайт может открываться с задержкой. Две версии используют отдельные базы: аккаунты и брони между ними не переносятся.

### Демо

Выберите аккаунт на экране входа или введите данные вручную:

| Логин | Пароль | Роль |
|---|---|---|
| `student1` | `campus2026` | Студент |
| `student2` | `campus2026` | Студент |
| `admin` | `campus2026` | Администратор |

Студенту доступны поиск, бронирования и раздел **«Встречи и очередь»**. Администратору — аудитории, все бронирования, статистика и CSV. Демо содержит 12 аудиторий и учебные брони. На Render данные демо временные и могут сбрасываться при пересоздании контейнера.

### Рабочая версия

Для регистрации студента получите код приглашения у администратора. После входа выберите аудиторию и время, затем подтвердите бронь. Свои встречи и отмена доступны в **«Мои бронирования»**, настройки профиля — по нажатию на аватар или имя в боковом меню.

Учебных аккаунтов здесь нет. Администратор добавляет аудитории через интерфейс; данные хранятся в PostgreSQL.

## Возможности

- Поиск по корпусу, вместимости, оборудованию и свободному времени; три рекомендации, точное время и альтернативы при отсутствии мест.
- **QR-страницы аудиторий** — доступность без входа, переход к бронированию после авторизации.
- **Текущая встреча** — подтверждение начала, продление и досрочное освобождение.
- **Честный доступ** — настраиваемые квоты пользователя и команды, длительность и горизонт бронирования.
- **Временные ограничения** — закрытие помещения или недоступность оборудования с проверкой затронутых броней.
- Календарь занятости, создание и отмена броней с сохранением истории.
- **«Поймать окно»** — очередь на подходящую аудиторию с удержанием слота на 5 минут.
- **«Собрать всех»** — голосование за время по ссылке без регистрации и выбор свободной аудитории.
- **«Подстраховка»** — до трёх вариантов замены отменённой аудитории с подтверждением переноса.
- **Команды** — приглашения по ссылке, роли, общий список встреч и ответы участников.
- **Регулярные встречи** — до 12 недель с проверкой каждой даты, пропуском конфликтов и заменой аудитории.
- **Почтовые уведомления** — подтверждение email, выбор событий и очередь доставки через Gmail / Google Apps Script без покупки домена.
- Профиль, смена пароля, завершение сессий, светлая и тёмная темы.
- Экспорт встречи в календарь `.ics`; управление аудиториями и статистика для администратора.

[Подробное описание новых функций для презентации](docs/FEATURES.md).

Время кампуса — **Екатеринбург, UTC+5**, бронирование доступно с **08:00 до 22:00**. При подтверждении система повторно проверяет занятость и не допускает пересечения активных броней. Администратор управляет бронированиями, но не создаёт их от своего имени.

## Команды, регулярные встречи и почта

В разделе **«Команды и встречи»** создайте команду и передайте приглашение участникам. Для вступления нужен аккаунт. Владелец назначает организаторов и исключает участников; организаторы назначают встречи. В разделе «Встречи и очередь» при создании голосования можно выбрать свою команду — ссылка появится и на странице команды.

Для серии выберите команду или личную встречу, аудиторию, первую дату и количество недель (1–12). Нажмите **«Проверить даты»**: для занятой даты выберите другую аудиторию и проверьте снова либо отметьте «Пропустить». Подтвердите список. Можно отменить одну встречу, изменить будущие встречи или отменить остаток серии. Ответ «Приду / Не смогу / Пока не знаю» относится ко всей серии.

В **профиле → Почтовые уведомления** можно подтвердить email и выбрать уведомления о встречах, вступлении в команду, предложениях очереди и напоминаниях за час. Если отправитель ещё не настроен, интерфейс сообщает об этом. Для реальной доставки оператор должен подключить Gmail через Google Apps Script и защищённое задание cron: **[пошаговая инструкция по бесплатной почте](docs/EMAIL.md)**. Создавать аккаунт провайдера для работы остальных функций не требуется. Ежедневные сводки и вложения `.ics` в письмах пока не поддерживаются; экспорт календаря доступен в интерфейсе.

## Новые инструменты кампуса

В поиске укажите начало и окончание: появятся до трёх подходящих аудиторий. Интервал переносится в подтверждение, его можно изменить с точностью до минуты. Если мест нет, доступны альтернативы в другом корпусе или со сдвигом начала до часа, а также очередь с уже заполненными условиями. Занятость обновляется каждые 30 секунд и при возвращении во вкладку.

В **«Мои бронирования»** во время встречи доступна кнопка **«Управлять встречей»**. Начало подтверждает организатор; продление проверяет занятость и правила, досрочное завершение освобождает оставшееся время. Автоматической отмены за неявку нет.

Администратор открывает **«Аудитории → Правила бронирования и временные ограничения»**. Квоты по умолчанию выключены (0); неделя считается с понедельника, UTC+5. Изменение правил не отменяет старые брони. Перед закрытием комнаты нужно проверить затронутые встречи и явно подтвердить их отмену. Снятие ограничения не восстанавливает отменённые брони автоматически.

У каждой аудитории есть раскрываемый **QR-код**, который можно скачать и распечатать. Создавайте коды на нужном публичном сайте: код из localhost ведёт на локальный сервер. Страница `/#room=ID` показывает занятость без персональных данных.

Миграция `0004` добавляет требования к оборудованию, принадлежность командной брони и отметку начала. Старые записи сохраняются; их требования к оборудованию неизвестны и требуют ручной проверки при поломке. В новых обычных бронях сохраняются выбранные фильтры оборудования, в планах — требования плана. Эти функции не требуют новых ключей или внешних сервисов. Почтовые предупреждения требуют ранее настроенной доставки.

## Запуск на своём компьютере

Нужны Git, запущенный Docker Desktop и интернет для первой сборки. Команды ниже выполняются в PowerShell из корня проекта.

```powershell
git clone https://github.com/bodhiswaga/hackathon-cf.git
cd hackathon-cf
```

Если проект уже скачан, откройте его папку в терминале.

### Демо: быстрый запуск

```powershell
docker compose -p campusflow up --build -d
```

Откройте **[127.0.0.1:8080](http://127.0.0.1:8080)** и войдите учебным аккаунтом. Миграции и демо-данные создаются автоматически. Локальное демо использует PostgreSQL и сохраняет данные между перезапусками.

```powershell
# Состояние контейнеров и логи приложения
docker compose -p campusflow ps
docker compose -p campusflow logs --tail=100 web

# Остановка с сохранением базы
docker compose -p campusflow down
```

### Prod-ready: отдельная база и реальные аккаунты

**1. Подготовьте настройки.** Если `.env.production` ещё нет:

```powershell
Copy-Item .env.production.example .env.production
```

Откройте `.env.production` и замените значения `POSTGRES_PASSWORD`, `JWT_SECRET` и `REGISTRATION_INVITE_CODE` тремя независимыми случайными строками. При установленном Python их можно получить командой:

```powershell
python -c "import secrets; print('\n'.join(secrets.token_hex(32) for _ in range(3)))"
```

Для локального запуска оставьте `ALLOWED_HOSTS=localhost,127.0.0.1`. Уже настроенный файл не перезаписывайте; секреты не публикуйте.

**2. Запустите приложение.**

```powershell
docker compose --env-file .env.production -f compose.production.yaml -p campusflow-prod-check up --build -d
```

**3. При первом запуске создайте администратора.**

```powershell
docker compose --env-file .env.production -f compose.production.yaml -p campusflow-prod-check exec web python -m backend.cli create-admin --login operator --name "Администратор кампуса"
```

Введите пароль минимум из 12 символов — при вводе символы не отображаются. Если аккаунт уже существует, используйте его.

**4. Откройте [127.0.0.1:8081](http://127.0.0.1:8081).** Войдите как `operator` и добавьте аудитории. Студенты регистрируются с кодом `REGISTRATION_INVITE_CODE` из `.env.production`. Учебные данные в этом режиме не создаются, миграции выполняются автоматически.

```powershell
# Состояние, логи и остановка
docker compose --env-file .env.production -f compose.production.yaml -p campusflow-prod-check ps
docker compose --env-file .env.production -f compose.production.yaml -p campusflow-prod-check logs --tail=100 web
docker compose --env-file .env.production -f compose.production.yaml -p campusflow-prod-check down
```

Оба режима можно запускать одновременно: порты и базы разные. Команда `down` сохраняет данные; `down -v` удаляет volumes. Смена `POSTGRES_PASSWORD` в файле не меняет пароль уже созданной БД. Локальные данные не синхронизируются с публичными сайтами.

## Render и cron-job.org

Для собственного развёртывания создайте два Blueprint из ветки `main`:

| Версия | Blueprint Path | Ресурсы |
|---|---|---|
| Демо | `render.yaml` | Free Web Service, временная SQLite |
| Prod-ready | `render.production.yaml` | Free Web Service и Free PostgreSQL |

Для prod-ready при первом развёртывании задайте `BOOTSTRAP_ADMIN_PASSWORD` — пароль администратора `operator` минимум из 12 символов. После успешного входа удалите эту переменную из Render Environment. Код приглашения студентов находится в `REGISTRATION_INVITE_CODE`.

Для проверки доступности создайте в [cron-job.org](https://console.cron-job.org/) по заданию GET на `/api/health` каждого сайта с интервалом 10 минут. Авторизация не нужна; **Test run** должен вернуть HTTP 200. Включите уведомления о сбоях.

Бесплатные сервисы имеют общий лимит 750 часов в месяц на workspace: два сайта не смогут работать круглосуточно весь месяц. Бесплатная PostgreSQL ограничена сроком 30 дней и требует самостоятельного резервного копирования. Cron не отменяет эти ограничения и не гарантирует непрерывную доступность.

**[Подробная настройка Render, расписания cron и резервного копирования →](docs/PRODUCTION.md#render-free-демонстрация-и-prod-ready-приложение)**

## API и проверки

[Swagger демо](https://campusflow-78s7.onrender.com/docs) содержит полный контракт API. При локальном демозапуске доступны `/docs` и `/openapi.json`; в prod-ready они отключены.

Основные маршруты с префиксом `/api`:

| Маршрут | Назначение |
|---|---|
| `POST /auth/login`, `POST /auth/register` | Вход и регистрация |
| `GET /auth/me`, `PATCH /auth/profile`, `POST /auth/password` | Аккаунт и профиль |
| `POST /auth/logout`, `POST /auth/logout-all` | Завершение сессий |
| `GET /rooms`, `GET /rooms/{id}/free-slots` | Поиск и свободное время |
| `POST /bookings`, `GET /bookings/my`, `DELETE /bookings/{id}` | Создание, просмотр и отмена броней |
| `GET /plans`, `POST /plans/queue`, `POST /plans/meeting` | Очередь и командные встречи |
| `POST /plans/{id}/confirm`, `DELETE /plans/{id}` | Подтверждение и закрытие плана |
| `GET /meetings/{token}`, `POST /meetings/{token}/votes` | Гостевая страница и голосование |
| `GET /bookings/{id}/alternatives`, `POST /bookings/{id}/replace` | Подбор и подтверждение замены |
| `/admin/rooms`, `/admin/bookings`, `/admin/stats`, `/admin/bookings.csv`, `/admin/audit` | Управление кампусом, только admin |
| `/teams`, `/teams/join`, `/teams/{id}/members/{uid}` | Команды, приглашения и роли |
| `POST /series/preview`, `POST /series`, `PUT /series/{id}`, `DELETE /series/{id}` | Проверка, создание, изменение и отмена серии |
| `GET /series`, `POST /series/{id}/rsvp` | Общие встречи и ответы участников |
| `GET /email`, `PUT /email`, `POST /email/verify` | Почта и подтверждение адреса |
| `POST /jobs/notifications` | Доставка и напоминания; отдельный секрет cron |
| `GET /booking-policy`, `PUT /admin/booking-policy` | Квоты и правила (изменение — только admin) |
| `GET /public/rooms/{id}` | Занятость на сегодня без персональных данных |
| `POST /bookings/{id}/check-in`, `PATCH /bookings/{id}/end-time` | Начало и окончание текущей встречи владельца |
| `GET/POST /admin/restrictions`, `POST /admin/restrictions/preview`, `DELETE /admin/restrictions/{id}` | Временные ограничения и предварительная проверка |
| `GET /health` | Проверка приложения и БД |

Для защищённых запросов передавайте `Authorization: Bearer <accessToken>`; токен возвращает вход. Данные — JSON, дата — `YYYY-MM-DD`, время — `HH:MM`. Успешное создание брони возвращает 201, конфликт — 409 `BOOKING_CONFLICT`, обращение к чужой брони — 403 `FORBIDDEN`. Отмена сохраняет запись в истории.

Для локальных API-тестов нужны Python 3.11+ и отдельное виртуальное окружение:

```powershell
python -m venv .venv
.venv/Scripts/python -m pip install -r requirements-dev.txt
.venv/Scripts/python -m pytest backend/tests -q
```

Backend проверен на SQLite и PostgreSQL; CI также собирает frontend и Docker-образ.
