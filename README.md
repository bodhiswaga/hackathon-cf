# CampusFlow

Веб-сервис бронирования аудиторий: поиск свободного помещения, организация встреч и управление занятостью кампуса.

**Стек:** React · TypeScript · FastAPI · SQLAlchemy · PostgreSQL / SQLite · Docker.

## Открыть сайт

| Версия | Адрес | Доступ |
|---|---|---|
| Демо хакатона | [campusflow-78s7.onrender.com](https://campusflow-78s7.onrender.com) | Учебные аккаунты ниже |
| Рабочая версия | [campusflow-production.onrender.com](https://campusflow-production.onrender.com) | Личный аккаунт; регистрация по приглашению |

На сайтах отдельные базы: аккаунты и брони между ними не переносятся. Почта подключена через Gmail / Google Apps Script. После простоя бесплатный Render может открываться с задержкой.

Учебные аккаунты **только для демо**:

| Логин | Пароль | Роль |
|---|---|---|
| `student1` | `campus2026` | Студент |
| `student2` | `campus2026` | Студент |
| `admin` | `campus2026` | Администратор |

## Что умеет CampusFlow

| Возможность | Как работает |
|---|---|
| Поиск и бронирование | Фильтры по корпусу, вместимости, оборудованию и времени; до трёх рекомендаций, точный интервал, альтернативы, отмена и история |
| «Поймать окно» | Очередь на подходящую аудиторию с удержанием предложения на 5 минут |
| «Собрать всех» | Голосование за время по гостевой ссылке и выбор свободного помещения |
| «Подстраховка» | Подбор замены отменённой аудитории с сохранением времени встречи |
| Команды и серии | Приглашения, роли, общий список встреч, ответы участников и еженедельные серии до 12 недель |
| Текущая встреча | Подтверждение начала, продление, досрочное завершение и автоосвобождение при неявке |
| Управление кампусом | Аудитории, все брони, квоты, временные ограничения помещений и оборудования, статистика, CSV и аудит |
| Профиль и уведомления | Аватар, отдельные имя и фамилия, переключение добавленных аккаунтов, подтверждение email, настройки писем и история доставки |

Есть светлая, тёмная и системная темы, мобильный интерфейс и экспорт встреч в календарь `.ics`. [Описание функций и примеры для презентации](docs/FEATURES.md).

## Как пользоваться

**Студент:** войдите → откройте «Найти аудиторию» → задайте дату и условия → выберите помещение → подтвердите время. Бронь появится в «Мои бронирования». Интервалы проверяются сервером; занятое время повторно забронировать нельзя.

**Командные встречи:** в «Команды и встречи» создайте команду и передайте приглашение участникам. Для серии задайте первую дату и количество недель, нажмите «Проверить даты», замените помещение или пропустите конфликтующие даты. Голосование и очередь находятся в «Встречи и очередь».

**Профиль:** нажмите на имя или аватар в боковой панели. Фото меняется нажатием на аватар в профиле; принимаются JPEG, PNG и WebP до 5 МБ. «Добавить аккаунт» позволяет войти в другой аккаунт и переключаться между действующими сессиями. До пяти аккаунтов сохраняются в текущей вкладке; пароли не сохраняются.

**Почта:** укажите email в профиле, подтвердите его по ссылке и выберите события. После трёх писем в предпросмотре остаётся последнее; через 15 минут предпросмотр скрывается. «Посмотреть все» раскрывает историю с прокруткой и датами по времени кампуса. Старые записи загружаются кнопкой «Ещё письма»; история не удаляется. У старых писем без сохранённого времени отправки есть соответствующая пометка.

**Администратор:** управляет аудиториями и всеми бронями, видит статистику и экспортирует CSV. В разделе «Аудитории» доступны QR-коды помещений, правила бронирования и временные ограничения. Перед закрытием занятой комнаты нужно проверить затронутые встречи и подтвердить отмену. Квоты по умолчанию выключены. Администратор не создаёт студенческие брони от своего имени.

Время кампуса — **Екатеринбург, UTC+5**, часы бронирования — **08:00–22:00**.

### Подтверждение встречи и автоотмена

Подтверждение доступно организатору за **10 минут до начала**. Без подтверждения через **10 минут после начала** сервер освобождает помещение и предлагает оставшееся время очереди. Проверка выполняется каждые 30 секунд; пользователь видит предупреждение, а при настроенной почте получает письмо.

Автоотмена требует непрерывного наблюдения за окном подтверждения и успешного входящего API-запроса не старше 90 секунд. Перезапуск, пропуск проверок более 90 секунд, обнаруженная ошибка сервера или загрузки JS/CSS защищают затронутую бронь от отмены. Поздно замеченные и уже завершившиеся встречи задним числом не отменяются. При неопределённости бронь сохраняется.

Для фоновой работы настройте cron `GET /api/health` **каждую минуту** в рабочие часы. Почтовая доставка настраивается отдельно.

## Локальный запуск

Нужны Git, запущенный Docker Desktop с Docker Compose и интернет для первой сборки. Команды выполняются в PowerShell из корня проекта.

```powershell
git clone https://github.com/bodhiswaga/hackathon-cf.git
cd hackathon-cf
```

Если проект уже скачан, откройте его папку.

### Демо: учебные данные

```powershell
docker compose -p campusflow up --build -d
```

Откройте **[127.0.0.1:8080](http://127.0.0.1:8080)** и войдите учебным аккаунтом из таблицы выше. Миграции и тестовые данные создаются автоматически: 12 аудиторий, три пользователя и брони на разные даты. Локальное демо использует PostgreSQL и сохраняет данные между перезапусками.

```powershell
# Состояние и логи
docker compose -p campusflow ps
docker compose -p campusflow logs --tail=100 web

# Остановка с сохранением базы
docker compose -p campusflow down
```

### Prod-ready: отдельная база и реальные аккаунты

1. Создайте файл настроек, если его ещё нет:

   ```powershell
   Copy-Item .env.production.example .env.production
   ```

2. В `.env.production` замените `POSTGRES_PASSWORD`, `JWT_SECRET` и `REGISTRATION_INVITE_CODE` тремя независимыми случайными строками. При установленном Python их можно сгенерировать так:

   ```powershell
   python -c "import secrets; print('\n'.join(secrets.token_hex(32) for _ in range(3)))"
   ```

   Используйте по одной строке на переменную. Hex-строка для пароля БД подходит для подключения без дополнительного URL-кодирования. Для локального запуска оставьте `ALLOWED_HOSTS=localhost,127.0.0.1`. Уже настроенный файл не перезаписывайте; секреты не публикуйте.

3. Запустите production-конфигурацию:

   ```powershell
   docker compose --env-file .env.production -f compose.production.yaml -p campusflow-prod-check up --build -d
   ```

4. При первом запуске создайте администратора:

   ```powershell
   docker compose --env-file .env.production -f compose.production.yaml -p campusflow-prod-check exec web python -m backend.cli create-admin --login operator --name "Администратор кампуса"
   ```

   Введите пароль минимум из 12 символов; символы при вводе не отображаются. Если администратор уже создан, используйте существующий аккаунт.

5. Откройте **[127.0.0.1:8081](http://127.0.0.1:8081)**. Войдите как `operator` и добавьте аудитории. Студенты регистрируются с кодом `REGISTRATION_INVITE_CODE`. Миграции выполняются автоматически, учебные данные не загружаются.

```powershell
# Состояние, логи и остановка с сохранением базы
docker compose --env-file .env.production -f compose.production.yaml -p campusflow-prod-check ps
docker compose --env-file .env.production -f compose.production.yaml -p campusflow-prod-check logs --tail=100 web
docker compose --env-file .env.production -f compose.production.yaml -p campusflow-prod-check down
```

Режимы можно запускать одновременно: порты и базы разные. `down` сохраняет данные, `down -v` удаляет volumes. Изменение `POSTGRES_PASSWORD` в файле не меняет пароль уже созданной базы. Локальные данные не синхронизируются с публичными сайтами.

Чтобы обновить существующий запуск, выполните `git pull`, затем повторите команду `up --build -d` выбранного режима. Для локальной отправки писем нужны дополнительные настройки из [инструкции Gmail](docs/EMAIL.md); без них остальные функции доступны.

## Render и cron-job.org

Для собственного развёртывания подключите репозиторий и ветку `main` через Render Blueprint:

| Версия | Blueprint Path | Хранение данных |
|---|---|---|
| Демо | `render.yaml` | Временная SQLite: изменения могут исчезнуть при перезапуске или деплое |
| Prod-ready | `render.production.yaml` | Отдельная PostgreSQL, реальные пользователи и регистрация по приглашению |

В production при первом деплое задайте `BOOTSTRAP_ADMIN_PASSWORD` для администратора `operator` — минимум 12 символов. После успешного входа удалите эту переменную. Код приглашения студентов — `REGISTRATION_INVITE_CODE`. Дальнейшие миграции выполняются при запуске сервиса.

Для каждого сайта настройте задания в [cron-job.org](https://console.cron-job.org/):

| Задание | Запрос | Авторизация | Расписание |
|---|---|---|---|
| Доступность и защита автоотмены | `GET https://<адрес-сайта>/api/health` | Не нужна | Каждую минуту в часы работы |
| Доставка писем | `POST https://<адрес-сайта>/api/jobs/notifications`, тело пустое | `Authorization: Bearer <NOTIFICATIONS_JOB_SECRET>` | Каждую минуту в часы работы |

Выполните **Test run**: ожидается HTTP 200. Включите уведомления о сбоях. Для почты сначала настройте Google Apps Script и переменные Render по [инструкции Gmail](docs/EMAIL.md). Демо и prod могут использовать один скрипт; `PUBLIC_URL` у каждого сайта свой, ключи cron рекомендуется разделить.

Бесплатный Render даёт общие **750 часов в месяц на workspace**: два сайта не смогут работать круглосуточно весь месяц. Free PostgreSQL действует **30 дней** и не имеет управляемых бэкапов. Cron не снимает эти ограничения. Рабочая конфигурация приложения на Free подходит для демонстрации и пилота; для постоянной эксплуатации нужны надёжное хранение и резервное копирование. [Ограничения Render](https://render.com/docs/free).

## API и проверки

[Swagger публичного демо](https://campusflow-78s7.onrender.com/docs) содержит полный контракт. В локальном демо доступны `/docs` и `/openapi.json`; в production они отключены.

Основные маршруты, все с префиксом `/api`:

| Маршрут | Назначение |
|---|---|
| `POST /auth/login`, `POST /auth/register` | Вход и регистрация |
| `GET /auth/me`, `PATCH /auth/profile`, `PUT /auth/avatar` | Профиль, имя, фамилия и фото |
| `POST /auth/password`, `POST /auth/logout`, `POST /auth/logout-all` | Пароль и сессии |
| `GET /rooms`, `GET /rooms/{id}/free-slots` | Поиск и свободное время |
| `POST /bookings`, `GET /bookings/my`, `DELETE /bookings/{id}` | Создание, просмотр и отмена броней |
| `POST /bookings/{id}/check-in`, `PATCH /bookings/{id}/end-time` | Подтверждение начала и изменение окончания |
| `/plans`, `/meetings`, `/teams`, `/series` | Очередь, голосования, команды и серии |
| `/admin/rooms`, `/admin/bookings`, `/admin/stats` | Управление кампусом; только admin |
| `GET/PUT /email`, `GET /email/history`, `POST /email/verify` | Настройки почты, история и подтверждение |
| `POST /jobs/notifications`, `GET /health` | Доставка писем и проверка приложения/БД |

Защищённые запросы принимают `Authorization: Bearer <accessToken>`; токен выдаётся при входе. Формат — JSON, даты `YYYY-MM-DD`, время `HH:MM`. Создание брони возвращает **201**, пересечение — **409 BOOKING_CONFLICT**, доступ к чужой брони — **403 FORBIDDEN**. Отмена сохраняет запись в истории.

Для backend-тестов нужны Python 3.11+ и отдельное окружение:

```powershell
python -m venv .venv
.venv/Scripts/python -m pip install -r requirements-dev.txt
.venv/Scripts/python -m pytest backend/tests -q
```

Для проверки frontend нужны Node.js 22+ и npm:

```powershell
cd frontend
npm ci
npm run build
npm test
```

CI проверяет backend на SQLite и PostgreSQL 17, frontend и Docker-сборку. Точные результаты и границы проверок — в [журнале проверок](docs/VERIFICATION.md).
